# MediDrop 0.1.7 — measured edge

**Pre-pilot foundation patch. Not `1.0.0` and not launch-ready.**

This release turns two previously open claims into repeatable gates, applies the deferred dependency
batch, and fixes the search-index mismatch that the new load gate exposed.

## 250K catalogue search

`infrastructure/scripts/catalogue-load-check.py` seeds **250,000** medicines plus one inventory row
per medicine, then measures 100 real HTTP searches through the API.

| Metric | Result |
| --- | --- |
| Dataset | 250,000 medicines + 250,000 inventory rows |
| Samples | 100 (after 10 warm-ups) |
| p50 | **189.1 ms** |
| p95 | **280.5 ms** |
| p99 | **286.8 ms** |
| Max | **288.5 ms** |
| Target | p95 < 300 ms |
| Errors / empty results | **0 / 0** |

The first run measured p95 298.5 ms. `EXPLAIN` showed the lowercased predicate scanning the raw-name
B-tree because V3 indexed the raw columns. V7 replaces those indexes with lowercased trigram
expression indexes and adds a prefix index for suggestions.

Environment: Linux x86_64, PostgreSQL 16 in Docker, Spring Boot 3.5.16, single API instance, warm
cache. This is a bounded local measurement, not a soak or multi-instance result. CI does not run the
250K gate.

## Browser and accessibility gate

Playwright **1.65.1** and axe-core/playwright **4.14.0** now run in the required frontend CI job at
390 × 844 in Chrome:

- home
- search
- medicine detail
- sign-in
- search → medicine detail journey

Result: **5 passed, 0 failed**, with zero WCAG A/AA axe violations on the four pages. The first run
found a real logo accessible-name mismatch; the implementation now uses the visible wordmark and
tagline, and no rule was suppressed.

This covers public pages only. Role dashboards, keyboard, screen-reader, Lighthouse and 1440 px
screenshots remain open.
