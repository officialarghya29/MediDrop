# MediDrop 0.1.6 — hardened edge

**Pre-pilot foundation release. Not `1.0.0`, not a licensed pharmacy service and not a
production-certification claim.**

This patch closes authorization edges that remained after the 0.1.5 provider-state pass, then adds
the runtime and repository controls needed to operate the same model predictably.

## Fixed

- **Suspended providers lose realtime access.** Pharmacy tracking subscriptions require an approved,
  active pharmacy. Rider delivery and tracking subscriptions require an approved rider. Suspension
  now blocks the live channel as well as REST writes.
- **Inactive pharmacies cannot receive prescriptions.** Prescription upload requires both approval
  and active state, closing the approved-but-inactive assignment path.
- **Checkout requires both contacts verified.** Email and mobile verification are both required
  before an order can be placed.
- **Production lifecycle is explicit.** Graceful shutdown drains for up to 30 seconds, Hikari leak
  detection is enabled, JDBC writes batch at 30, and liveness/readiness probes are available for
  orchestration.

## Repository controls

- `main` now rejects force-pushes and deletion and requires the three CI jobs for pull requests.
  Admin direct pushes remain available for this release rail.
- CI gates the production npm tree with `npm audit --omit=dev --audit-level=high`.
- Dependabot now limits automatic PRs to minor/patch updates. Eight unsafe major upgrades were
  closed with a migration rationale instead of being merged on partial compatibility coverage.
