# MediDrop 0.1.5 — provider state authority

**Status: foundation release. Pre-pilot; not `1.0.0`.**

This release closes a second authorization gap: a provider suspended after login could still act on
work assigned before the suspension. It also converts the long-standing 50-way stock claim into a
measured, repeatable gate.

## Fixed

- **Suspended riders lose delivery authority.** Accepting, advancing and completing an assignment
  now require an `APPROVED` partner. A suspension that lands after assignment cannot be bypassed by
  staying logged in.
- **Suspended pharmacies lose fulfilment authority.** Accept, prepare and ready-for-pickup transitions
  require an approved, active pharmacy. Cancellation remains available to close an existing order.
- **Suspended pharmacies lose prescription access.** Review, queue, review history and prescription
  file reads require an active approved pharmacy, so suspension removes PHI access immediately.
- **Inventory writes follow the same state.** Stock, batch and medicine maintenance require an active
  pharmacy.

## 50-way stock gate

`infrastructure/scripts/stock-race-check.py` seeds 50 customers and carts, then fires 50 simultaneous
COD checkouts at one real inventory row with stock 10.

Measured on fresh PostgreSQL 16:

| Result | Count |
| --- | ---: |
| HTTP `200` orders | 10 |
| HTTP `409` insufficient stock | 40 |
| Orders created | 10 |
| Stock remaining | 0 |
| SALE ledger units | 10 |
| Other responses / server errors | 0 |

This closes the 50-way evidence gap, not the 250K catalogue or sustained-load gates.
