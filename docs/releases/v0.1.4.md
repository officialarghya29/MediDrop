# MediDrop 0.1.4 — model hardening

**Status: foundation release. Pre-pilot; not `1.0.0`.**

This release hardens failure paths that could otherwise produce a wrong identity or order outcome.

## Fixed

- **OTP cannot bypass account state.** Locked, disabled and deletion-pending accounts are refused
  before a verification attempt can mint an access/refresh pair.
- **Single-use tokens are enforced under concurrency.** OTP and password-reset rows are read with
  pessimistic write locks; two simultaneous requests cannot both consume the same token.
- **Order transitions are version-guarded.** `Order` now carries an optimistic version and migration
  `V6` adds the PostgreSQL column. A stale cancellation, acceptance or refund attempt receives a
  recoverable conflict instead of silently overwriting a newer state.
- **Rejected riders no longer strand orders.** Reassignment runs in `DELIVERY_ASSIGNED` state,
  replaces the rider, refreshes the handover code and keeps the lifecycle moving forward.
- **Version truth in the console.** The stale `v1.0` label is replaced with the actual release line.
