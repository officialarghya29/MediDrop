# Accessibility register

Last updated: 2026-11-20

Status: **PARTIAL. Public pages, checkout and all three role dashboards have automated axe coverage; Lighthouse accessibility is measured. Keyboard, screen-reader, touch-target, Ops Night and i18n audits remain open.**

This register records what exists in the code, what is missing and what must be proven before
the v5 WCAG AA claim. Static presence of an ARIA attribute is not a pass.

## 1. v5 requirements

- WCAG AA.
- Keyboard navigation.
- Touch targets at least 44px.
- Loading, empty, error and success states on every screen.
- axe zero serious/critical findings.
- Screenshots at 390px and 1440px.
- Light and Ops Night modes for pharmacy, delivery and admin.
- English, Hindi and Bengali UI.
- Honor `prefers-reduced-motion`.

## 4. 0.1.8 evidence

- Browser command: `cd frontend && npm run build && npm run test:e2e`.
- Browser tools: Playwright **1.65.1**, axe-core/playwright **4.14.0**, system Chrome **158**,
  390 × 844 viewport.
- Browser scope: home, `/search?q=Paracetamol`, `/medicines/1`, `/login`, search → detail, plus
  `/checkout`, `/pharmacy`, `/delivery` and `/admin` with role-scoped fixtures.
- Browser result: **9 passed, 0 failed**; zero WCAG A/AA axe violations.
- Lighthouse: pinned **12.8.2**, mobile form factor, three runs per URL against the built preview
  with the real API proxied. Median accessibility **100** on home and search; performance **92** and
  **93**. Full summary in `docs/assets/lighthouse-v018.json`.
- Two real defects were fixed rather than suppressed. The 0.1.7 gate found the logo's accessible-name
  mismatch; the 0.1.8 Lighthouse run found an h1 → h3 heading-order jump on the search results, now
  corrected with a hidden level-two heading.
- Limitation: deterministic API fixtures for authenticated pages. The axe run does not prove
  keyboard order, focus traps, screen-reader output, touch-target size, 1440 px layout, Ops Night or
  i18n. Lighthouse covers only the public home and search screens.

## 5. Required gate for M14

1. Extend the axe browser gate to tracking, order detail, prescriptions and the remaining console
   subpages.
2. Run Lighthouse on checkout, tracking and the admin screens as well as home and search.
3. Record a keyboard-only pass and a screen-reader pass.
4. Measure touch targets; fix failures rather than suppressing rules.
5. Add a skip link and complete modal focus trap/restore behaviour.
6. Add 390px and 1440px screenshots in light and Ops Night modes.
7. Add i18n and a PWA manifest/service worker, then re-run the gate.
8. Publish the exact tool versions and reports beside the result.
